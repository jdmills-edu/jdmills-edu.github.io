Diagnosing a temperamental Linux AI workstation

Troubleshooting

A desktop that also runs a 27B model across two GPUs breaks in strange ways. Claude reads the journal, kernel and driver logs alongside me and tests one theory at a time. Again and again, the symptom points somewhere other than the cause.

  • Linux
  • NVIDIA
  • GNOME
  • Wayland
  • systemd
  • netconsole

Examples 7

  1. The "freezes" were failed resumes from sleep

    Fourteen of 36 boots ended on a suspend line, so the desktop was sleeping after 15 idle minutes and failing to wake. Masking the sleep targets fixed it.

  2. An invisible pointer that was really a VRAM shortage

    The cursor vanished while clicks still worked, because the LLM server had left the display GPU too little memory for the cursor sprite. A per-GPU margin fixed it, once we saw llama.cpp numbers the GPUs in the reverse of nvidia-smi's order.

  3. Black screen after the monitor sleeps

    The NVIDIA driver kept failing to retrain the HDMI 2.1 FRL link for the 240 Hz mode. The fix is DisplayPort, and a rescue script drops to 60 Hz and retries in the meantime.

4 more examples

  1. Every GNOME extension silently switched off

    A shell crash at startup tripped GNOME's safety switch. The first check missed it because Homebrew's gsettings can't see the real settings.

  2. Two apps quietly rendering on the CPU

    SDR++ in a container with no NVIDIA libraries was software-drawing its waterfall at 830% CPU, and grafting in the host driver took it to 1–2%. Separately, a stale Flatpak override had a slicer stuck in software GL.

  3. A global setting flipped which GPU an app used

    A system-wide CUDA_DEVICE_ORDER, added for one app, inverted another app's GPU pinning. Each launcher now sets both variables explicitly.

  4. A hard freeze, and a crash log that had stopped working

    Two freezes under dual-GPU load left nothing in the journal, and the remote kernel log had gone silent days earlier when the receiving machine's MAC changed. That's fixed and checked now, though the root cause is still open.

Drivers, devices and networks that misbehave

Troubleshooting

When hardware drops out or the network crawls, the job is evidence first: log the fault automatically, then separate the causes. Most of these turned out to have more than one.

  • Linux kernel
  • SELinux
  • USB
  • ethtool
  • IPv6
  • macOS

Examples 4

  1. A brand-new Wi-Fi 7 card on an immutable distro

    An out-of-tree driver, relabelled so SELinux lets it load at boot, plus a sideloaded Bluetooth firmware blob. Both are set to retire themselves once the kernel catches up.

  2. "Downloads keep failing": four causes at once

    A cable that kept dropping the link to 100 Mb, a Flatpak service stuck in a restart loop eating bandwidth, IPv6 that black-holed some sites, and a 1420-byte path MTU. Three of the four were local.

  3. An audio interface that fell off USB on its own

    A five-second monitor logged every drop. Clean disconnects with no host errors, in escalating bursts, pointed at the device's power path, not drivers or firmware.

1 more example

  1. A permission prompt nobody could click froze a headless Mac

    Services on a Mac mini hung in open() because macOS's privacy daemon was waiting on a consent prompt, set off when a Homebrew upgrade changed a binary's path. Moving their data out of the protected Documents folder ended it.

Related projects: Backyard bird detector, Solar & battery inverter dashboard

Software-defined radio, from receivers to noise hunts

Radio & RF

RTL-SDR dongles, SDR++ and HF antennas, with Claude doing the signal analysis: envelope spectra to tell interference from stations, repeatable noise-floor sweeps, VNA calibration, and patches when the tools themselves break.

  • RTL-SDR
  • SDR++
  • PipeWire
  • NanoVNA
  • RFI
  • DSP

Examples 6

  1. Tracing radio noise to a monitor's power supply

    A 20 dB jump in the noise floor pulsed at exactly 250 Hz, so it was power electronics, and the source was an OLED monitor next to the coax. Hash stamps the same envelope on every frequency, while a real signal stays in its own channel.

  2. SDR dongles dropping off USB, and the hub behind it

    Each dropped dongle shifted device indices, so servers grabbed the wrong radio, and a monitor went deaf for 11 days. The cause was a USB sub-hub. Pin devices by serial, not index.

  3. Measuring an antenna with unlabelled calibration parts

    Claude drove the NanoVNA over USB, identified the open, short and load caps from their phase readings, calibrated, and plotted SWR across four bands.

3 more examples

  1. A repeatable noise-floor test for antenna changes

    A direct-sampling sweep over rtl_tcp turns "did that help?" into before-and-after numbers. Let the tuner settle after each retune.

  2. The CW "noise" that was really the AGC

    The howl between Morse characters was the AGC adding up to 140 dB of gain in each pause, which recordings showed. The speech denoiser used for voice turned out to erase CW entirely, so routing now follows the mode.

  3. SDR++ playing into the wrong output, and crashing at startup

    RtAudio saw one device name for three PipeWire sinks, so a launcher now moves the stream. A divide-by-zero race was fixed by rebuilding the core library at the package's exact commit.

Related projects: Orbic SDR server, NanoVNA toolkit, SDR++ noise reduction, Spectrum sweeper station

Radio software that can't transmit by accident

Radio & RF

Rig control, decoders and mesh radios for a new ham. The rule is that nothing gets keyed during development: transmit paths are tested against simulated radios, and live testing is receive-only.

  • Yaesu CAT
  • FCC Part 97
  • FT8
  • CW
  • Meshtastic
  • simulation

Examples 4

  1. A transmit-capable console that never transmitted

    Receive-only is the default and enforced in the CAT layer, and a licence-privilege engine decides what's allowed where. Every transmit path was tested only against a simulated radio, in dozens of safety cases.

  2. The radio console that started listening to the room

    When the radio's USB audio dropped, PipeWire quietly switched capture to a webcam mic. Capture is now pinned by device name, and fixing clipping took false Morse characters from about 245 a minute to none.

  3. "No FT8 signals" was really a stale clock

    The handheld's self-tests passed, but its clock was weeks off and FT8 needs it within about a second. With the clock set, two minutes on 20 m gave 42 decodes.

1 more example

  1. Mesh radios that may not have shared a frequency

    Meshtastic derives the frequency slot from the channel name, so a receive-only probe listened on both candidates. The likeliest culprit turned out to be a stale phone-to-radio Bluetooth link.

Bringing up and rescuing small embedded boards

Hardware & firmware

ESP32 handhelds, Meshtastic nodes and a Flipper Zero. Claude reads firmware source and schematics and drives serial consoles, and when the firmware is missing a feature it writes a throwaway one.

  • ESP32-P4
  • ESP-IDF
  • esptool
  • Meshtastic
  • Flipper Zero
  • USB

Examples 6

  1. The "boot loop" that was my own serial console

    The board wires DTR/RTS straight to its reset pin, so every port open rebooted it. A small service now holds the port quietly.

  2. Two different reasons for "CARRIER WAITING"

    One was a frequency below the radio chip's range. The other was a hung USB dongle that no software could power-cycle, because the switch's enable pin is tied to 5 V.

  3. A throwaway firmware just to format an SD card

    The card was exFAT, which the firmware can't read, and the firmware has no format command. A purpose-built formatter went into the app slot, did the job, and the original firmware went back on.

3 more examples

  1. Turning a microcontroller into a USB card reader

    Temporary mass-storage firmware loaded an offline street map (cut from OpenStreetMap data into PMTiles) and 600 MB of music in about 24 minutes. The card's own write speed was the real limit.

  2. A flashing script that clobbered the OTA partition

    Meshtastic's bundled script wrote the filesystem at a hard-coded offset that is wrong on 16 MB boards. Flashing by hand with esptool, at the release's own offsets, fixed it.

  3. Testing a Flipper app without touching the Flipper

    The serial CLI can drive a running app (input send), check for crashes (loader info) and check for leaks (free), so every build gets a scripted smoke test.

Related projects: LakeShark FT-891 app, Kid-friendly mesh messenger watch, Morse Beacon for Flipper Zero

Customising a stream deck and a Bluetooth dial

Hardware & firmware

A 15-key OpenDeck stream deck and a Bluetooth knob became a control surface for the whole desk: live GPU and inverter tiles, a radio tuning knob, noise-reduction and lighting keys. Claude writes the plugins, works out each device's quirks, and reads the hardware state back instead of trusting the plugin.

  • OpenDeck
  • Stream Deck plugins
  • Input Remapper
  • D-Bus
  • hidraw
  • OpenRGB
  • Python

Examples 5

  1. Plugins with nothing but the standard library

    The OpenDeck Flatpak sandbox has Python but no pip, so the tile plugin brings its own WebSocket client and a tiny PNG painter. It draws GPU sparklines and VRAM bars plus battery, load and grid tiles, and only redraws a key when its output changes.

  2. GPU tiles that don't shuffle when a card disappears

    The tiles stream nvidia-smi from outside the sandbox, with slots fixed by PCI bus ID. If the external GPU drops off its link, its tile says "offline" instead of the other card sliding into its place.

  3. A six-mode dial, switched from a deck key

    Each mode (volume, scroll, zoom, scrub, undo, lights) is an Input Remapper preset swapped over the system D-Bus, and a deck key shows and cycles the current one. Homebrew's own gdbus quietly talked to the wrong bus until the system binary was used.

2 more examples

  1. The dial as a radio tuning knob

    In radio mode the shack console reads the knob's raw HID events and tunes the VFO, with spin acceleration (up to 20× steps, capped at 50 kHz) and coalesced CAT writes. It was tested against a fake radio and a fake dial before going near the real ones.

  2. RGB keys that reach what OpenRGB can't

    OpenRGB skips a board whose headers report zero LEDs, and the RAM only appears after login. The case fans on the 12 V header needed raw-HID packets: mode on effect channel 1, colour in slot 5, both found by testing live.

Related projects: Desk control surface, SDR++ noise reduction, FT-891 Shack Console

Running a local LLM well

AI & local models

One 27B model on two consumer GPUs serves an assistant, a TV and Claude Code. That means measuring instead of guessing, patching model files and message formats, and bounding how long the model thinks.

  • llama.cpp
  • GGUF
  • speculative decoding
  • Claude Code
  • speech-to-text

Examples 4

  1. Grafting a missing speculative-decoding head back into a model

    Community exports had silently dropped the 15 MTP tensors, because Transformers discards modules it doesn't know. They were fetched by HTTP byte range, grafted back in, and the model re-quantised.

  2. Pointing Claude Code at the home model

    llama.cpp already speaks Anthropic's API, but Claude Code's trailing system message broke the model's chat template, so a small shim folds it in. Watching its sockets confirmed it never contacted anything off the machine.

  3. The assistant that thought for six minutes

    After a tool error the model reasoned for 342 seconds and timed out. A finite reasoning budget fixed it, and short replies now skip thinking (2.7 s down to 1.3 s).

1 more example

  1. Picking speech-to-text for a TV that talks back

    Parakeet on the CPU beat Moonshine and Whisper at about 60 ms per utterance, with no GPU needed. Short names were the weak spot until the vocabulary was biased toward them.

Making AI features behave

AI & local models

Getting an assistant to be useful without being wrong or reckless. Again and again, the fix moves a rule out of the prompt and into code.

  • agents
  • MCP
  • grounding
  • intent parsing
  • n8n

Examples 4

  1. Making an AI ask before it deletes

    Prompt rules didn't stop the assistant removing calendar items. Now a change only runs after a second call with a single-use confirmation code, so when the model fired "yes" 30 times in a loop, only the first got through.

  2. Stopping trivia about the wrong thing

    Wikipedia search had quietly "corrected" an unknown channel name into a common word, so the TV showed facts about the wrong subject. Every name word in the query must now appear in the matched article.

  3. "Get rid of the meow" added another meow

    Keyword rules treated every mention as a request to add. Removal intent now wins, with word boundaries, since "pulsing" contains "sing".

1 more example

  1. When an LLM can't hum, look the tune up

    Melodies come from a songbook, then free MIDI files (with the lead line extracted), and only last from the model's memory.

Guardrails for real-world home devices

Home & automation

Software that touches a solar inverter or the family TV has to fail safe and stay fast on a phone, and it has to be debugged without assuming the worst.

  • Modbus
  • MQTT
  • Android TV
  • ADB
  • SQLite

Examples 3

  1. Guarding an inverter's settings below the UI, not in it

    The gateway underneath accepted writes to every register, so its map now allows only 16. The app adds read-back after each write, an audit log, and preview-first AI tools.

  2. A phone dashboard that downloaded 13 MB to draw a chart

    Bucketing history on the server with a covering index cut 30 days of data to 36 KB, loading in about 180 ms.

  3. The TV that "died" was just very asleep

    A crashed system process left the chip in deep sleep with Wi-Fi off for nearly seven hours. It wasn't bricked, and there's now a recovery procedure.

Getting data back, and making it searchable

Data recovery

Recovering files from a damaged volume and keeping an overnight OCR job alive over thousands of PDFs, all on copies first, with every recovered file checked before calling it done.

  • ext3
  • fsck
  • PhotoRec
  • OCR
  • Ghostscript
  • Kiwix

Examples 3

  1. Recovering files from a crash-corrupted encrypted volume

    Running fsck on a dd image reattached about a thousand orphaned files with their full content, after undelete tools had found nothing. Force PhotoRec to a 4 KB block size, or every carved file stops at 64 KB.

  2. Rescuing an overnight OCR job and the PDFs that hung it

    An OS update swapped out the job's Python. Re-encoding with Ghostscript turned 4-hour hangs into 6-second jobs, and 10 of 11 broken books became searchable.

  3. Making 400 GB of offline books searchable

    Apple's Vision OCR beat Tesseract at 0.44 against 1.6 seconds a page, and plain-file text beat a SQLite database shared across the Docker VM boundary.

Examples 3

  2. One-key bug reports from inside a game

    This site rebuilds itself daily, and a privacy scan blocks the push if a name, address, hostname or callsign slips into the output. Images are re-encoded to strip metadata and checked by eye before they're approved.
